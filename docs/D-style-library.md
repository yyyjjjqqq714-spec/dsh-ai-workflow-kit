## 1. 统一字段表（19 个字段）

### 1.1 业务字段（你要求的 11 个）

| # | 字段 | 类型 | 已有映射 | 填写要求 |
|---|------|------|----------|----------|
| 1 | `name` 风格名 | string | `name` ✅ | 中文短名，≤8 字，避免"高级感"这类空词 |
| 2 | `definition` 定义 | string | `look` ✅ | 一句话说清"画面在发生什么"，≤40 字。必须是**可看见的物理描述**，不是形容词堆砌 |
| 3 | `keywords` 关键词 | string[] | `kw` ✅ | 4-8 个，中英各半。英文词用于直接喂 AI 视频模型 |
| 4 | `fit_scenarios` 适用场景 | string[] | `fit` ✅ | 3-6 个，写"什么内容配这个风格"，不写"什么都能用" |
| 5 | `script_structure` 脚本结构 | object | ❌ 新增 | 见 1.3，四段式时长比例 |
| 6 | `camera_rhythm` 镜头节奏 | object | ❌ 新增 | 见 1.3，切镜频率/运动幅度/景别倾向 |
| 7 | `prompt_template` 提示词模板 | string | ❌ 新增 | 带 `{{占位符}}`，可直接复制使用，50-150 字 |
| 8 | `negative` 负面约束 | string[] | ❌ 新增 | 5-10 条，写"不要什么"，针对该风格最容易出现的失败 |
| 9 | `example` 示例 | object | ❌ 新增 | 一句真实可用的完整输入（含主题+时长+平台） |
| 10 | `workflow_node` 工作流节点 | string[] | ❌ 新增 | 该风格应挂在流程哪个环节，见 1.4 |
| 11 | `qc_gates` 质检点 | object[] | ❌ 新增 | 3-6 条可打勾的检查项，见 1.5 |

### 1.3 script_structure 与 camera_rhythm 的结构

```jsonc
"script_structure": {
  "hook":    {"ratio": 0.10, "desc": "前 3 秒抓人：一个反常识结论或强对比画面"},
  "build":   {"ratio": 0.45, "desc": "展开：3 个递进论据，每 8-12 秒一个信息点"},
  "turn":    {"ratio": 0.25, "desc": "转折：推翻前面的一半假设"},
  "landing": {"ratio": 0.20, "desc": "落地：一句可被截图传播的话"}
},
"camera_rhythm": {
  "cut_rate": "2-4 秒/镜",
  "motion": "缓推为主，无手持抖动",
  "framing": "中景偏特写，人物居中偏左",
  "transition": ["硬切", "叠化（仅段落间）"]
}
```

### 1.4 workflow_node 可选值（固定枚举，别自由发挥）

```
research      选题调研
outline       结构大纲
script        口播/脚本撰写
storyboard    分镜
visual_gen    画面生成（AI 或代码）
shoot          实拍
voice         配音/口播录制
edit          剪辑
subtitle      字幕
audio         配乐/音效
package       包装（花字/动效/LOGO）
publish       发布适配（封面/标题/尺寸）
```

### 1.5 qc_gates 的结构

```jsonc
{"check": "前 3 秒是否出现明确冲突或悬念", "auto": false, "fail_action": "重写 hook"}
```
- `auto: true` 表示可由脚本自动判定（如时长、分辨率、字幕是否存在）
- `auto: false` 表示必须人工看一眼

## 5. 每批的处理工序（6 步，固定 SOP）

```
① 选：从大类里挑本批条目（S1 从 catalog.json 按 kind/bodyLen 筛；新类从候选清单挑）
② 读：只读这 25 条原文（S1 的 md 原文在 F:\skill提示词库\...）
③ 填：按 19 字段补全，script_structure/camera_rhythm 必须结合原文 specs 推导，不许编
④ 验：prompt_template 实际复制到 AI 里跑一次，确认能出片（这是"可复制"的唯一验证）
⑤ 校：validate.mjs + 与已有条目查重
⑥ 记：batch-NN-report.md + 更新 _index.json
```

**铁律**：
- `definition` 必须是"可看见的物理描述"，禁止"很有质感""高级感"这类空词
- `negative` 必须针对**该风格特有的失败模式**，不能全批复制同一段
- `prompt_template` 里的 `{{占位符}}` 必须是真正需要替换的变量，不要留无意义占位

## 6. 质检点标准（qc_gates 怎么写才算合格）

| 风格类型 | 必须有的质检点（示例） |
|----------|------------------------|
| 文字类 | 首帧是否可读 / 最长停留是否够读完 / 有无裁切 |
| 人物类 | 人脸是否变形 / 手部是否异常 / 口型是否同步 |
| 包装类 | 数据是否与脚本一致 / 品牌色是否准确 / 安全区是否越界 |
| 音频类 | 卡点误差是否 <2 帧 / 有无爆音 / 字幕与音频是否同步 |
| AI 生成类 | 有无闪烁 / 有无肢体增删 / 是否跨镜一致性 |

每条 `qc_gates` 必须有 `fail_action`（检查不过时怎么办），否则等于没写。
